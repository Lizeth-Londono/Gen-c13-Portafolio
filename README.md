# 🧩 Arquitectura de la introducción

Actualmente la introducción trabaja con dos estructuras diferentes.

## Retícula principal

```text
14 columnas
×
10 filas
=
140 celdas
```

Su función es representar información inicial mediante:

- números;
- símbolos;
- pequeños fragmentos binarios;
- caracteres relacionados con código.

JavaScript genera las celdas dinámicamente a partir de una distribución previamente definida.

Algunos caracteres utilizados son:

```text
0  1  3  5  8
<  >  =
{  }  ;
#  %
/  //
?  &
L  X
```

También se utilizan pequeñas secuencias binarias como:

```text
01
10
101
010
001
110
1010
```

---

## Retícula del emblema

Después de diferentes pruebas se decidió utilizar una matriz independiente de:

```text
30 columnas
×
30 filas
=
900 celdas
```

Esta retícula permite contar con mayor resolución para construir una versión modular del emblema.

Inicialmente se realizaron pruebas con:

```text
20 × 20
=
400 celdas
```

pero se identificó que esta resolución limitaba demasiado algunas formas.

Por esta razón se evolucionó progresivamente hacia:

```text
30 × 30
=
900 celdas
```

La intención no es reproducir el emblema con precisión profesional.

El objetivo actual es construir una representación modular suficientemente clara para:

- demostrar el concepto;
- aplicar lo aprendido;
- comprender el código;
- explicar el proceso;
- continuar mejorándolo en el futuro.

# 🔢 Construcción del emblema

El emblema no se está construyendo mediante una imagen pegada directamente sobre la página.

Se trabaja mediante una matriz de valores:

```text
0
=
celda inactiva

1
=
celda activa
```

JavaScript recorre el mapa y agrega una clase CSS a las posiciones que pertenecen a la figura.

Este proceso permite reforzar conceptos como:

- arreglos;
- matrices;
- recorridos;
- índices;
- ciclos `for`;
- condicionales;
- `.flat()`;
- `classList.add()`;
- manipulación del DOM;
- `createElement()`;
- `appendChild()`;
- separación entre lógica y presentación.

# 🎬 Arquitectura planteada para las futuras animaciones

Cuando se retome esta etapa se busca mantener una separación de responsabilidades sencilla:

```text
CSS Grid
→ estructura de las retículas

CSS
→ apariencia y estados visuales

JavaScript
→ creación de elementos

JavaScript
→ cambio de estados mediante clases

CSS transitions / keyframes
→ movimiento visual
```

La intención es evitar colocar estilos directamente desde JavaScript cuando pueden controlarse mediante clases.

Por ejemplo:

```javascript
elemento.classList.add("estado-activo");
```

y permitir que CSS determine cómo debe verse ese estado.

# 🎨 Referente visual

Para la introducción se tomó como referencia conceptual el proyecto:

## F13 Code Summit

**Plataforma:** Behance

[F13 Code Summit — Proyecto de referencia](https://www.behance.net/gallery/252670417/F13-Code-Summit?tracking_source=for_you_logged_in_feed_published)

Del proyecto resultaron interesantes especialmente:

- la composición con caracteres;
- el uso de números, letras y símbolos;
- la estética vinculada con programación;
- la tipografía modular;
- la formación progresiva de una identidad;
- el contraste entre fondo oscuro y colores brillantes;
- la narrativa de reorganización visual.

La referencia se utiliza únicamente con fines de inspiración, documentación y aprendizaje.

No se busca copiar:

- su logotipo;
- su nombre;
- sus composiciones exactas;
- su secuencia;
- sus textos;
- sus fotografías;
- su identidad visual;
- su resultado final.

La intención es reinterpretar su principio visual mediante:

- la identidad LXL;
- el concepto CODE x LIHEN;
- símbolos propios;
- paleta propia;
- textos propios;
- contenido profesional propio;
- una narrativa de concentración desde los bordes hacia el centro.

Todos los derechos del proyecto de referencia pertenecen a sus autores originales.
